# 音频处理说明

## 端点与音源

- 活动设备由 `MMDeviceEnumerator.EnumerateAudioEndPoints(..., DeviceState.Active)` 枚举；显示名称、默认标记和稳定 `MMDevice.ID`。
- 麦克风使用 `WasapiCapture(selectedMMDevice)`；系统声音使用 `WasapiLoopbackCapture(selectedMMDevice)`。二者均默认共享模式。
- Loopback 是所选播放端点的系统输出混音，不是“按进程”或“默认麦克风”采集。
- `IMMNotificationClient` 监听添加、移除、状态、属性和默认端点变化，150 ms 去抖后刷新 UI。
- 已选设备不可用时保留不可用占位项，不静默替换设备。用户可重新选择并启动。

## 处理链

```text
WASAPI 回调（一次必要内存复制）
  → 有界原始队列（512000 字节/源；满时丢新帧）
  → 后台 PCM/float 解码、各声道平均降混
  → WDL 重采样至 16 kHz
  → PCM16，严格 20 ms / 640 字节分块
  → [混合模式] 单调时间戳对齐 + 浮点增益 + 限幅
  → 有界识别队列（128000 字节，约 4 秒；满时丢新帧）
  → 可替换识别提供程序 → 顺序翻译最终结果 → UI Dispatcher
```

- 音频回调不执行重采样、网络、UI 或异步等待。
- 混合器每路最多缓存 500 ms；使用单调输出 deadline，每次最多输出一块，不追赶输出未来音频。两路按样本时间戳对齐，偏移区域补零，只混合实际重叠样本。一路缺失时短暂等待后以静音补齐；长期无输入时不产生静音帧。
- 两路设备不是同一硬件时钟，本实现做软件时间戳/样本计数对齐并限制漂移缓冲；不是采样级硬件同步。长时间漂移及具体设备音质需 Windows 实测。
- 混合结果是一路 16 kHz、单声道、PCM16，不保留双路独立声道。

## 生命周期

采集仅由用户显式开始。停止先停所有 WASAPI 源，再完成识别队列；识别最多有 3 秒完成最终结果，之后取消。设备或处理故障触发相同清理路径。`finally` 中释放其余源和事件，避免单端点异常阻断清理。

无后台自启动、无隐藏录音、无默认音频落盘。进程/性能采样脚本不会自行开启采集。
